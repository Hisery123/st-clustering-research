# 第三篇论文：低成本成熟基线增量改进路线 V1

状态：**研究策略与第一轮 MVP 设计，未执行新的改进实验**。建立于 2026-11-10 用户明确讨论；不是新成果的证据。

## 目标与工作方式

- 实际目标：争取符合毕业要求的普通 SCI/相应期刊论文，优先**低投入、可复现、有限创新**，不以顶刊级理论突破为目标；不保证 SCI 四区录用。最终目标期刊须复核当年索引、分区和毕业要求。
- 工作方法：**成熟基线 → 可测弱点 → 一个最小改动 → 低成本开发集 MVP → 预先锁定的必要对照/验证 → 与实验同步写作**。不把不必要的长篇文献审查、无关历史调试当成继续工作的阻塞条件；遇到不影响当前结论的旧 GMM seed0 差异仅记录，不主动重启。
- AI 做科研指导、脚本和 GitHub 文档；用户在 Windows 实际执行，**一次一条 PowerShell 命令**，回传输出后才进入下一步。
- 允许开发集上探索多种真实可解释的配置，保存完整尝试记录（含失败/无改进），如实报告方法选择；但**不能将同一开发集上百次挑出的最好成绩当独立测试成效**。不要把挑选出来的少数实验包装成全部消融实验。
- 低成本不降低的三个底线：真实数据与可核实引文；结果、假设和计划分开；人工标签不能流入独立测试阶段的模型选择。Oracle-K7 是参考标签类别数参与协议，必须明示，不能说完全无监督。
- 基线可不必完全复制作者所有硬件/版本，但将运行方式准确命名为 adapted baseline，论文比较要使用统一且透明的实验条件。

## 当前可证据支持的痛点

CellCharter v0.3.2 adapted，DLPFC 151507、seed22911、Oracle-K7，一份 scVI 5D latent，L0-L4 输入维度5/10/15/20/25，GMM各拟合。L4 151507 ARI 0.496146、NMI 0.675436；L5/L6边界0/145、L4/L5约3/160；L0碎片化严重。F1并不单调、某些上层组织边界召回在L4反弹。只是观察，**不能归因为已经证明的“过度平滑”**。L0-L4 不仅深度变化，也改变特征维度与 GMM 拟合，因此需要谨慎解释。

## 第一轮最小实验的具体范围

先使用已保存 **seed22911 L4 25维 CellCharter 特征**，完全不动 scVI 和空间图，先测试分块统计诊断的可行性：

- 自身表征 L0：列0:5；1–4跳邻域聚合块：各5列，共25维。
- 第一条只读脚本 [preflight_multiscale_blocks_151507.py](../../scripts/cellcharter/preflight_multiscale_blocks_151507.py) 只计算每块 MeanAbs、RMS、列标准差、同维与自身的绝对相关均值及原文件SHA256，不加载人工标签、不拟合 GMM、不写文件。
- 若各块的尺度明显不均衡，再**预先冻结小规模候选**：原始 L4、简单分块等尺度校准、预设固定邻域衰减权重；都在 25维与一致的 GMM 协议下完成一次开发集比较。对角缩放是可逆变换，在理想 full-covariance GMM 下理论上可由协方差吸收，若观察到变化需特别谨慎检查初始化、正则化与数值求解，**不能宣称发明了新表达模型**。
- 若统计无明显尺度不均衡，不为了凑论文强行使用标准化；优先换用具有明确假设的特征消融/多尺度融合检验。新的方法候选、实现和取值要在看开发集新结果之前锁定并写进计划。
- 本轮 MVP 不以“151507 上某个边界改善”作为唯一判据；至少同时报告整体 ARI/NMI、全局边界 P/R/F1、6个层间界面、各层内假分割、运行时间、失败。若出现 ARI 或边界 F1 降低，原样报告。
- 简单尺度加权已有大量类似思想（AugGCL/CodaST等），只能作为**已有机制的控制/试验性优化**，不能仅凭名称改写冒充独创算法。

## 论文工作量的有限闭环

1. **开发**：151507已反复使用人工标签，仅当开发集，不可作为新独立盲测。先测试最少量候选，记录全部结果；如实际不改善则及时止损。
2. **对照**：同一 scVI representation / 25维输入 / GMM求解预算、同一 seed 和完整统一评价；加最简单对照及删除模块消融。无法控制的因素必须明示。
3. **验证**：方法冻结后再选已审查独立性的其他样本/供体；151508历史曾探索，应核实其数据使用史。独立实验单位是供体/切片而不是空间边。
4. **写作**：现阶段就可开始标题草案、研究问题、Methodology骨架、真实基线设置、结果表格结构；模型提升/新方法名称/显著性只能填入验证后的数据。

## 第一项可执行步骤

Windows 先将 GitHub 最新脚本拉到本地（无需用户手动维护 GitHub 文档），然后单独运行只读 `scripts/cellcharter/preflight_multiscale_blocks_151507.py`。执行成功标志：`MULTISCALE_BLOCK_PREFLIGHT_COMPLETE; NO_LABELS; NO_GMM; NO_FILES_WRITTEN`。如 25维文件缺失则诊断，不自动重算原特征。
